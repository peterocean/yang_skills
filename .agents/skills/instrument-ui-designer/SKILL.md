# 仪器软件界面对话式设计

用简体中文引导用户从需求到可确认的界面预览，再形成可实施规格。图片中的产品名、单位、信号名和代码符号保持用户给定写法。

## 工作原则

- 把用户已经提供的内容直接记为已确认，不重复提问。
- 将每个关键结论标记为“已确认”“暂定”或“待确认”；暂定值必须说明理由，并允许用户一句话修改。
- 优先询问会改变画布、色彩能力、交互方式或代码架构的事项。低影响细节留到预览迭代时确认。
- 不把生成式图片中的文字、坐标或控件细节当作工程真值。概念风格可用图像生成；需要精确文字、比例和像素时，使用 SVG、HTML/canvas、桌面绘图或目标中间件模拟器生成确定性预览。
- 不在用户确认高保真预览前直接扩展为整套业务页面或生产代码，除非用户明确要求边设计边实现。
- 保留已锁定的设计项。后续修改若会影响锁定项，先指出联动影响再继续。
- 在生成第一张图片前确认图片输出目录。确认后自动将本轮线框图、风格图和高保真预览保存到该目录，并在回复中给出实际保存路径。

## 建立设计简报

开始时收集设备用途、主要读数、关键操作、告警等级和操作者环境，然后确认以下六项核心因素以及图片输出目录。用户不确定时给出 2–3 个适合其设备的选项和一个明确推荐，不要只抛出术语。

1. **屏幕分辨率**：物理/逻辑宽高、横竖屏、旋转方向、安全边距；区分屏幕分辨率与参考图片尺寸。
2. **屏幕类型**：TFT LCD、OLED、单色 LCD、电子纸等；补充彩色/单色、触摸类型、圆形或矩形、刷新限制及强光使用情况。
3. **像素格式**：例如 1 bpp、RGB332、RGB565、RGB888、ARGB8888；实现阶段再确认通道顺序、字节序、alpha 与帧缓冲限制。
4. **显示风格**：工业、实验室、医疗、科技、极简、复古仪表等；确认明暗主题、主色、信息密度、品牌色和可参考/应避免的界面。
5. **GUI 中间件**：LVGL、TouchGFX、emWin、Qt、直接帧缓冲或其他方案；确认版本、语言、可用组件和现有工程限制。
6. **整体布局**：信息层级、功能区、页面数量、导航方式、主数据/趋势/状态/操作区的位置，以及物理键、旋钮或触摸输入。
7. **图片输出目录**：确认工作区内的相对目录或完整路径。目录不存在时自动创建；目录不可写或超出当前授权范围时，说明原因并请用户指定可写目录，不得静默改存到其他位置。

第一轮可以将“分辨率 + 屏幕类型 + 像素格式 + 中间件 + 图片输出目录”合并询问，第二轮确认“显示风格 + 整体布局”。若用户一次给全，直接进入汇总确认。完整的确认卡和结构化记录格式见 [references/design-brief.md](references/design-brief.md)。

发现明显冲突时先解释影响并给替代方案，例如：

- 单色屏、低位深格式不适合依赖渐变、透明度或仅靠颜色区分状态。
- RGB565 需关注渐变色带、半透明合成和显存占用。
- 电子纸不适合频繁动画、实时波形或大面积连续刷新。
- 无触摸屏时，导航、焦点和操作必须映射到实体键或旋钮。
- 中间件版本不明时，不生成带版本特定 API 的最终代码。

## 三个确认门

### 1. 约束确认

把已知信息整理为一张短表，明确六项核心因素、图片输出目录、业务内容、输入方式和未决项。请用户确认“按此进入线框设计”。仍有未知值时可以提出推荐暂定值，但不得静默假设。图片输出目录未确认前，不生成或保存图片。

### 2. 线框与布局确认

先提供 2–3 个有实质差异的布局方向，而不是只换颜色：例如主读数优先、趋势优先、控制优先。每个方向说明信息层级、适用操作、优点和代价。

为候选方向生成与目标屏幕同纵横比的低保真线框图。关键区域使用稳定名称和真实示例数据；不要让装饰掩盖布局。请用户选择一个方向，并确认需要调整的区域。选择后记录已锁定的区域、导航和核心控件。

### 3. 视觉与高保真确认

基于已选线框生成 2–3 个视觉方案，保持布局一致，只改变颜色、字体气质、层级、边框、圆角、阴影、图标语言等视觉变量。预览必须符合屏幕类型和像素格式的能力边界。

先用概念图确认风格，再用确定性方式生成目标分辨率高保真预览。向用户明确询问：选择哪个方案、哪些元素保留、哪些元素修改、是否批准进入实现规格。每轮只呈现有意义的变化，并更新已锁定项。

## 图片生成与评审

生成预览时，在提示或绘制参数中包含：

- 精确画布宽高和方向，以及界面必须铺满画布；
- 仪器用途、目标操作者、环境和输入方式；
- 固定的区域结构、控件清单、示例读数、单位和状态；
- 屏幕技术、像素格式、允许的调色板与不允许的效果；
- 选定的风格词、视觉令牌和参考图中要继承/避免的特征；
- 禁止生成设备外壳、手、透视场景、营销海报和无关装饰，除非用户确实需要整机效果图。

预览后检查纵横比、信息完整性、文字可读性、主次层级、状态区分、触控热区或键盘焦点、颜色/位深可实现性。图像生成造成的乱码必须在确定性预览中替换，不要求用户把乱码当作最终文案。

将所有图片自动保存到已确认的输出目录。按阶段使用稳定、可排序的文件名，例如 `01_wireframe_a.png`、`02_style_dark.png`、`03_hifi_approved.png`；同一次生成的 SVG、PNG 或原始像素文件使用相同主文件名。默认不覆盖已有文件：发现重名时追加递增版本号；只有用户明确要求覆盖时才替换。保存完成后核对文件存在、图片尺寸正确，并列出每个文件的完整路径。临时渲染文件放在输出目录的 `temp` 子目录；可将其列为清理候选，但未经用户同意不删除。

若用户提供参考图，先说明将继承哪些视觉特征，不照搬品牌标识或与目标硬件冲突的效果。若用户要求依据已有截图直接生成 LVGL 样式与代码，改用 `lvgl-style-extractor`。

## 形成工程规格

用户批准高保真预览后，交付：

1. 最终约束表与仍存在的假设。
2. 页面树、导航模型和每页区域说明。
3. 颜色、字体、间距、圆角、边框、图标、状态和动效令牌；不支持动效时明确删除。
4. 控件清单，包含 ID、类型、父级、边界、状态、数据源、交互和优先级。
5. 与目标 GUI 中间件匹配的布局映射和资源清单。
6. 目标分辨率 PNG 预览；需要烧录或比对时再输出用户要求的原始像素格式。所有图片保存在已确认的输出目录。
7. 验收清单：分辨率、裁切、单位、极值、告警、断线/无数据、禁用态、焦点或触摸操作、目标硬件实机色彩。

用户要求生成代码时，先读取其工程约定或样板文件，确认中间件版本和集成入口。生成内容不得凭空引用字体、图标、图片或驱动；缺少资源时使用清晰的占位说明。常见屏幕和中间件的决策提示见 [references/implementation-notes.md](references/implementation-notes.md)。

## 对话收尾

每个确认门结束时都给出一份简短“当前已锁定 / 尚待确认 / 输出目录 / 下一步产物”。不要笼统询问“满意吗”；用可执行的问题让用户选择方案或指出具体区域、颜色、密度和交互修改。
