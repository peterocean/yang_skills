# 屏幕与中间件实现提示

仅在选择技术方案、生成高保真工程预览或实现代码时读取。

## 屏幕与像素格式

| 条件 | 设计约束 | 预览与验收重点 |
| --- | --- | --- |
| 单色 1 bpp | 用形状、线型、填充纹理和文字共同编码状态 | 关闭抗锯齿或按实际引擎模拟；检查反色与抖动 |
| RGB332 / 索引色 | 控制调色板数量，避免相近状态色 | 用目标调色板量化后检查可辨识性 |
| RGB565 | 避免细腻暗部渐变与过多半透明叠加 | 导出 RGB565 再回显，检查色带和通道顺序 |
| RGB888 | 色彩限制较少，但仍核对带宽与帧缓冲 | 检查实际面板色域与亮度 |
| ARGB8888 | 支持透明合成，但显存和带宽较高 | 核对 alpha 合成路径和双缓冲预算 |
| OLED | 关注纯黑、峰值亮度、烧屏和长期静态元素 | 长时间状态栏和高亮元素需降低烧屏风险 |
| 电子纸 | 减少动画和大面积刷新，设计局部刷新区域 | 检查残影、刷新延迟和黑白/三色限制 |

原始像素文件导出前必须确认：颜色通道顺序、大小端、行对齐、旋转、扫描方向、alpha 预乘和文件头要求。PNG 预览不能证明这些参数正确。

## GUI 中间件

### LVGL

- 确认 v8 或 v9，不混用 API。
- 将颜色、字体、间距和尺寸集中为令牌；共享外观用 `lv_style_t`，业务差异用显式辅助函数或局部样式。
- 控件状态映射到正确的 `part` 与 `state`，并确认显示驱动的色深配置与刷新缓冲。
- 用户从参考截图反推现有界面时，转用 `lvgl-style-extractor`。

### TouchGFX

- 明确 Designer 版本、目标 MCU/显示接口、是否使用 framebuffer compression 和可用的字体/图片转换器。
- 将页面区分为 Screen 与可复用 Custom Container；动画需按帧率和带宽预算验证。

### emWin

- 确认 emWin 版本、Widget 支持、内存设备配置、字体格式和显示驱动。
- 先判断是否适合使用 Window Manager，避免把所有元素都实现成无层级的直接绘制。

### Qt / Qt for MCUs

- 区分桌面 Qt Quick、Qt Widgets 与 Qt for MCUs；三者的资源与控件假设不同。
- 确认触摸、GPU/加速、字体和目标平台约束，再选择阴影、模糊和动画。

### 直接帧缓冲或自研 GUI

- 先定义坐标系、裁剪、字体栅格化、脏矩形、输入分发和状态管理。
- 输出基础绘制原语与组件边界，不假设已有布局、动画或主题系统。

## 工程预览验收

- 使用目标逻辑分辨率生成无缩放截图。
- 覆盖最短/最长文本、最大/最小读数、负号、小数位和单位切换。
- 覆盖正常、警告、危险、无数据、断线、禁用和操作中状态。
- 验证文本和关键图形不只依赖颜色表达含义。
- 触摸界面核对热区、误触间距和手套操作；非触摸界面核对焦点顺序、返回路径和旋钮步进。
- 在目标硬件或等效模拟器上复核字体、色彩、刷新、撕裂、残影和性能。
