# LVGL 界面样式提取

根据用户提供的界面图片，输出可编译的 LVGL 控件样式与布局骨架，尽量复现可见的层级、几何、色彩、边框、圆角、阴影、文字与状态外观。所有面向用户的提问、说明、表格和结论使用简体中文；图片中的文字、文件路径、代码符号和器件名称保持原样。

## 输入与范围

先检查是否已收到清晰截图。若缺少影响生成的关键资料，使用中文一次性询问：

- 目标 LVGL 主版本（v8 或 v9）及可用主题/组件库；未指定时，默认 v9 并在输出中明确该假设。
- 图片原始像素尺寸，以及目标显示屏的逻辑分辨率、方向与色深。
- 是否需要仅提取样式，还是同时生成页面和控件创建代码；默认同时生成。
- 字体文件/字号要求、图标或图片资源的原文件；没有原文件时，不要伪造可用字体、图标或位图资源。

如果用户明确希望缩小界面，以图片尺寸为基准计算 `scale = min(target_width/source_width, target_height/source_height)`；保留比例、居中后的剩余边距，并将最终像素值取整。不要只按宽度缩放而忽略屏幕纵横比。

## 视觉提取

按视觉层级识别页面背景、顶栏/底栏、容器、卡片、分隔线、按钮、标签、图片、图标、进度/滑块、开关、列表、输入框和对话框。对每个候选控件记录：边界框、父子关系、可见状态、填充色、边框、圆角、阴影、内外边距、文字颜色/对齐/估计字号，以及是否需要图片资源。

区分三种信息：

- **图片可直接确认**：几何关系、可见颜色、层级和明显的边框/圆角。
- **合理推断**：控件类型、状态机、字体粗细、阴影参数。
- **需要资源或确认**：不可辨认文字、品牌字体、图标源文件、动态行为、不可见状态。

不要将截图中无法辨认的像素或隐藏交互行为宣称为已确认事实。

## 生成 LVGL 代码

先给出“控件与样式清单”，列出每个控件的 ID、推断类型、缩放后坐标/尺寸、关键样式和证据等级。随后先生成可直接保存为 `ui_<page>_style.h` 的 C 宏定义，再生成使用这些宏的一份自包含 LVGL C 代码片段。

宏默认使用 `UI_` 前缀；用户提供页面名或前缀时使用其指定名称。按屏幕、调色板、布局、卡片、文字、导航和控件状态分组。每个宏必须为有效 C 预处理器常量：尺寸与坐标使用整数，颜色使用 `0xRRGGBB`，不在宏中嵌入 `lv_color_hex()` 或其他函数调用。代码引用颜色时使用 `lv_color_hex(UI_COLOR_...)`。

为图片中每个可见控件输出其边界、间距、边框宽度、圆角/斜角近似值、字号和颜色宏；同一视觉令牌必须复用同一宏。对不确定参数使用带 `TODO` 的普通 C 注释，不生成伪精确的宏。不要把文字、图标或位图资源转换为样式常量，除非用户明确要求。

- 用独立的 `static lv_style_t` 保存可复用样式，并只初始化一次。
- 对每个控件设置父对象、位置、尺寸、对齐、样式和可见文字；将颜色写为 `lv_color_hex(0xRRGGBB)`。
- 按用户指定的 LVGL 大版本调用 API；未确认版本时，生成 v9 代码并显著标明，不要混用 v8/v9 API。
- 对缩放后的样式值使用命名常量或缩放辅助宏，避免散落的魔法数字。
- 使用占位注释标识缺少的图像、字体或图标，例如 `/* TODO: 提供 icon_home 资源 */`，而不是生成虚构资源。

输出时明确哪些控件使用 `LV_PART_MAIN`、`LV_PART_INDICATOR`、`LV_PART_KNOB`、`LV_PART_ITEMS` 或其他必要部件，并对默认状态、按下状态、禁用状态等仅在截图有证据或用户提出要求时添加样式。

## 交付格式

按以下顺序回答：

1. 图片与目标分辨率、LVGL 版本、缩放比例的假设。
2. 控件与样式清单。
3. 可直接保存的 C 宏定义头文件。
4. 使用这些宏的可直接集成 LVGL C 代码。
5. 需用户补充的资源与不确定项。
6. 建议在目标设备或 LVGL 模拟器中核对的视觉差异。

不要声称截图转换可像素级还原。字体渲染、抗锯齿、资源本身、主题默认值及实际显示屏色彩都可能造成差异。
